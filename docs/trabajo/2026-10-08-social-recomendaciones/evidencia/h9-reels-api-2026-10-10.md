# H9 — Reels API inicial y base compatible (2026-10-10)

Se implementó el primer slice backend de publicación y feed propio. El backend acepta solo `video/mp4` y `video/quicktime` y valida el contenedor ISO BMFF antes de almacenar. La comprobación de duración usa `mvhd`, `mdhd` y `elst`; contrasta los tiempos con `stts` y valida las tablas de muestras `stsz`, `stsc`, `stco`/`co64` y que sus rangos apunten dentro de `mdat`. Compara el límite de 90 s con aritmética entera y rechaza marcas MP4 falsas, contenedores truncados, fragmentados, ambiguos, muestras fuera de rango y archivos sin pista de video. La publicación es síncrona y crea `READY` solo después de validar y almacenar el archivo. La respuesta apunta a `/me/reels/:id/media`, una ruta autenticada que comprueba propietario y estado antes de leer el objeto.

El feed inicial devuelve únicamente reels `READY` del usuario actual. No se habilitó visibilidad de conexiones, guardados, reposts, comentarios, worker ni recorte/portada. El parser valida metadatos temporales y estructura/rangos de muestras, pero no decodifica ni transcodifica el codec. Como smoke independiente se generó un MP4 real de 1 s con ffmpeg y el parser reportó 1 s; esto no demuestra decodificación ni reproducción y no reemplaza un pipeline de transcodificación.
